# Opportunity Discovery v1

## 1. Why discovery is separate

Candidate evaluation assumes an idea already exists. The system must also help create candidate ideas from market evidence.

## 2. Discovery unit

Candidate seed:

```text
core_loop × theme × optional trend layer × production profile
```

## 3. Discovery signals

Look for combinations such as strong peer quality + healthy traction + non-exploding supply + theme momentum + low production burden.

Other useful patterns:

```text
proven mechanic + emerging theme
proven theme + underserved core loop
high-quality peers + low recent release rate
cross-market growth + weak Yandex supply
high-failure market → explicit avoid signal
```

## 4. Discovery does not equal decision

Discovery produces a candidate seed plus why it surfaced. Candidate evaluation then builds a full dossier.

## 5. Candidate generation pipeline

```text
market-state snapshots
→ taxonomy aggregation
→ theme trend aggregation
→ supply/quality/traction features
→ production feasibility filters
→ candidate seeds
→ dedupe / novelty checks
→ deep candidate evaluation
```

## 6. Avoid trend spam

Do not ingest all internet trends blindly. Use taxonomy to constrain external trend research to candidate themes, mechanic-adjacent themes, and fast-rising cultural entities.

## 7. Initial discovery heuristics

Before backtested models, use transparent/versioned heuristics and later evaluate them historically.
