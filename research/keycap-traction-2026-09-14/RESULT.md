## Methodological finding: do not chase a live search set

A later same-day collector run using the same versioned query suite changed three lexical `direct_candidate` IDs. The fail-closed analyst finalizer correctly refused to bind the previous review to the new semantic hash.

That failure is informative:

1. Yandex search ordering/surface can change between nearby observations.
2. Analyst review must bind one exact frozen semantic artifact, never an ambient latest search run.
3. Exact-title search does not guarantee recall of a known listing in the configured first three pages.
4. More same-day synonym expansion would not resolve this evidence problem and would instead move the target surface again.

Therefore run `34831092303` is explicitly designated the canonical search baseline for future longitudinal comparison. The final reviewed evidence was rebuilt **offline** from that exact frozen artifact.

## Interpretation

What is supported:

- Keycap/keyboard ASMR is a real and currently active Yandex product theme.
- At least three current direct click/upgrade/customize executions exist.
- The core can be implemented with very low complete production burden.
- Adjacent keyboard-customization games can acquire materially stronger rating traction.

What is **not** supported:

- strong current acquisition for the cheap direct keycap-clicker core;
- a claim that keyboard theme alone transfers the adjacent obby traction to the direct thesis;
- a platform-wide competitor count from the 344-member frozen search surface;
- a zero-miss search result from three pages per query;
- current growth velocity from a single rating-count observation.

The three observed direct executions currently sit around roughly **0.56–0.90 lifetime ratings/day**, which is interesting enough to keep watching but not strong enough to justify queue interruption on this evidence alone.

**Stop now:** no more same-day Keycap query expansion, no additional broad crawl, no production promotion.
